## Sprint 2: 体験の作り込み ―「初見の人が、説明なしで遊び始めて、また遊びたくなる」状態にする

### ゴール

Sprint 1 で「1台で最後まで遊べる」状態になったが、**ルールを口頭で説明しないと遊び始められない**（読み手/聞き手の役割、端末を見てはいけないという物理ルールがアプリ内のどこにも書かれていない）、および**遊び終わったあとの手応えが数字だけで、もう一度遊ぶ動機が薄い**という2点が残っている。

Sprint 2 では、アプリを初めて開いた人が **アプリ内の情報だけで正しく遊び始められる** ようにし、ゲーム終了時に **結果が「出来事」として感じられる** ところまで仕上げる。あわせて、ストア公開後にレビューが自然に集まる仕込み（レビュー訴求）を入れる。

---

### スコープ判断の理由

**Sprint 2 に含めるもの**

| 含めるもの | 理由 |
|---|---|
| 「遊び方」画面（新規） | **本スプリント最大の未実装項目**。本作は「読み手だけが画面を見る」「聞き手は音読だけで当てる」という物理的な運用ルールが成立しないとゲームにならない。前作のタブーワード方式より説明が必要で、spec.md でも優先度「高」に置かれている。現状アプリ内にルール説明が一切存在しない |
| ホーム / スタート設定への導線追加 | 遊び方画面を作っても、入口がなければ誰も読まない。spec.md の画面構成でもホームの要素として「遊び方」が挙げられている |
| リザルト画面の演出強化 | spec.md の画面構成でリザルトの要素として挙げられている「称賛メッセージ」が未実装。現状は数値3つが並ぶだけで、ゲームの締めとして弱い |
| レビュー訴求 | 実装は小さいが、**回数カウントの蓄積がストア公開前から始まっている必要がある**（公開直後にレビューが付くかどうかは初期の評価に直結する）。Sprint 3 の課金実装より先に仕込んでおく方が安全 |

**Sprint 2 から外すもの**

| 外すもの | 理由 |
|---|---|
| ホーム / スタート設定画面の**ビジュアルの作り直し** | Sprint 1 とその後の追加修正で、両画面ともブランドトーン（ネイビー/クリーム/コーラル、押し込まれた駒のセグメント、マスコット、流れる演出のデモパネル）に沿って十分に仕上がっている。Sprint 2 では**情報設計上の欠落（遊び方への入口がない／選択した速度が確認パネルに出ない）だけを補い、完成しているビジュアルには手を入れない** |
| リプレイ機能（説明文をもう一度流す救済措置） | ユーザー判断により**不要と決定**。spec.md からも削除済み |
| リザルトからの即リトライ（「もう一度遊ぶ」ボタン） | spec.md のリザルト画面の要素に含まれていない。またリプレイ機能を不要とした判断の趣旨（救済・やり直し系の導線を増やさない）に沿い、Sprint 2 では追加しない。HOME → GAME START で再開できる |
| テーマパック選択UI、ストア画面、RevenueCat 連携 | パックが1つしかない現状では選択UIが無意味。課金基盤ごと Sprint 3 に集約する。**ホームやスタート設定に「ストア」のプレースホルダーを置くこともしない**（押せない入口はユーザーを混乱させる） |
| ハイスコアの記録・表示、効果音・触覚フィードバック | spec.md で優先度「低」。レビュー訴求で使う永続ストレージの基盤は Sprint 2 で入るため、ハイスコアは後から低コストで追加できる |
| アイコン・スプラッシュ・プライバシーポリシー・ストア掲載情報 | リリース準備は Sprint 4 |

**検証環境について**: Evaluator は Playwright（Expo Web）で検証する。レビュー訴求の OS 標準ダイアログは Web では表示されないため、本スプリントの契約では **「表示条件を満たす回数が永続ストレージに正しく蓄積されること」と「非対応環境でゲーム進行を一切妨げないこと」** を検証対象とする。

### 実装する機能

- **機能A: 「遊び方」画面（新規）**
  新しい画面 `/how-to-play` を追加する。初めて開いた人が、口頭の補足なしに1ゲーム目を正しく始められることをゴールとする。最低限、以下を伝える。
  1. **役割** — 読み手は1人、端末を持って音読する。聞き手は1人以上、**画面を見ない**でお題の単語を当てる
  2. **流れる演出** — 説明文は画面下から上へ自動で流れる。流れ切る前に読み切るのがゲーム。実際の流れる演出のミニデモを画面内に置き、文章で説明するのではなく**動いているものを見せる**
  3. **判定** — 聞き手が当たったら「✓ CORRECT!」で +1点、読めない/わからないときは「SKIP」、猶予時間まで操作がなければ自動で次のお題へ進む
  4. **端末の持ち方・遊び方のコツ** — 端末は読み手だけに見えるように持つ、制限時間とスクロール速度はスタート設定で変えられる
  画面からは、ホームに戻る導線と、そのままゲームを始める導線の両方を出す。

- **機能B: ホーム / スタート設定の導線整理**
  ホームに「遊び方」への導線を追加する（GAME START を主役のまま保ち、遊び方は副次的な扱いにする）。スタート設定画面からも遊び方を開けるようにする（設定を選ぶ段階でルールを確認したくなるため）。加えて、スタート設定画面下部の確認パネルに **選択中のスクロール速度**を表示し、「制限時間 と 速度 の2つを選んだ」ことが開始直前に一目で確認できるようにする（現状は制限時間しか出ていない）。**両画面の既存のビジュアルデザインは変更しない。**

- **機能C: リザルト画面の演出強化**
  最終スコアを 0 から最終値へカウントアップさせ、結果が「開示される」演出にする。スコアに応じた**称賛メッセージ**（spec.md のリザルト画面要素。0点でも前向きな文言になるよう段階を設計する）を表示する。あわせて**正答率**と、**そのゲームの条件（制限時間 / スクロール速度）** を表示し、「次は速度を変えて挑戦する」という次の一手が自然に見えるようにする。

- **機能D: レビュー訴求**
  ゲーム終了（リザルト到達）のたびにゲーム完了回数を永続ストレージへ記録し、一定回数に達して以降、クールダウン期間を超えている場合にのみ OS 標準のレビューダイアログを控えめにリクエストする。姉妹プロジェクト `taboo-english-game` の `apps/mobile/lib/reviewPrompt.ts` の方針（最低3回完了 / 60日クールダウン / 失敗は握りつぶす）を踏襲してよい。**非対応環境（Web など）や失敗時にゲーム進行を妨げない**ことを絶対条件とする。

### スプリント契約（完了条件）

以下の全条件を満たした場合のみ、このスプリントは完了とする。

**遊び方画面（機能A）**

- [ ] ホーム画面に「遊び方」への導線が存在し、タップすると遊び方画面が表示される
- [ ] 遊び方画面に、読み手の役割と聞き手の役割の両方が明示されており、「聞き手は画面を見ない」という趣旨の記述が含まれる
- [ ] 遊び方画面に、説明文が画面下から上へ自動で流れることの説明と、実際に動いている流れる演出のデモが表示される（静止画やテキストのみではない）
- [ ] 遊び方画面に、「✓ CORRECT!」で加点されること、「SKIP」では加点されないこと、操作しなければ自動で次のお題へ進むことの3点が記載されている
- [ ] 遊び方画面に、制限時間とスクロール速度をスタート設定で変更できる旨の記述が含まれる
- [ ] 遊び方画面から「ホームに戻る」導線をタップするとホーム画面に戻る
- [ ] 遊び方画面からゲームを始める導線をタップするとスタート設定画面に遷移し、そのまま「START!」でプレイを開始できる
- [ ] スタート設定画面からも遊び方画面を開くことができ、そこから戻ったあとも制限時間・速度の選択に影響しない（遊び方を開く前に選んでいた組み合わせが失われても、再選択して正常に開始できる）
- [ ] 遊び方画面の表示中にコンソールエラーが発生しない

**ホーム / スタート設定の導線（機能B）**

- [ ] ホーム画面で「GAME START」が引き続き最も目立つ主要ボタンであり、「遊び方」がそれより控えめな見た目で配置されている
- [ ] ホーム画面・スタート設定画面のいずれにも、押しても何も起きない「ストア」等のプレースホルダーが存在しない
- [ ] スタート設定画面の確認パネルに、選択中の制限時間と**選択中のスクロール速度**の両方が表示される
- [ ] スタート設定画面で速度の選択を「簡単 / 普通 / 難しい」の間で切り替えると、確認パネルの速度表示が即座に追従して変わる

**リザルト演出（機能C）**

- [ ] リザルト画面に切り替わった直後、最終スコアが 0 から最終値へ増えていくカウントアップ演出が見え、演出の終了時点では最終値が正確に表示されている
- [ ] リザルト画面に、最終スコア・正解数・スキップ数に加えて**称賛メッセージ**が表示される
- [ ] 1問も正解できなかった場合（スコア0）でもリザルト画面が正常に表示され、称賛メッセージが空欄やエラー表示にならず、否定的でない文言が出る
- [ ] スコアが高い場合と0点の場合とで、異なる称賛メッセージが表示される
- [ ] リザルト画面に正答率が表示され、正解数とスキップ数から計算した値と一致する（例: 正解3 / スキップ1 → 75%）
- [ ] 1問も出題されずにゲームが終了した場合でも、正答率の表示が `NaN` や `Infinity` にならない
- [ ] リザルト画面に、そのゲームで選択した制限時間とスクロール速度が表示され、スタート設定画面で選んだ内容と一致する
- [ ] リザルト画面の「HOME」をタップするとホーム画面に戻り、再度ゲームを開始するとスコア0・カウントアップ演出も0からやり直される

**レビュー訴求（機能D）**

- [ ] リザルト画面に到達するたびに、ゲーム完了回数が永続ストレージに記録され、1ずつ増える
- [ ] 完了回数が既定の最低回数（3回）に満たない間は、レビューのリクエストが行われない
- [ ] レビュー訴求はゲーム進行をブロックしない（レビュー関連の処理が失敗する環境でも、リザルト画面のスコア・正解数・スキップ数・HOME ボタンがすべて正常に表示・操作できる）
- [ ] Expo Web（レビューダイアログ非対応環境）でゲームを最後まで遊んでも、レビュー関連の未処理例外がコンソールに出ない
- [ ] アプリを再読み込みしても完了回数が保持され、0にリセットされない

**堅牢性・回帰**

- [ ] 幅375pxのビューポートで、遊び方画面のすべての内容にスクロールで到達でき、横スクロールが発生しない
- [ ] 幅375pxのビューポートで、リザルト画面の追加要素（称賛メッセージ・正答率・ゲーム条件）を含めたすべてが画面内に収まるか縦スクロールで到達でき、横スクロールが発生しない
- [ ] Sprint 1 の契約が引き続きすべて満たされている（カウントダウン、流れる説明文の速度が単語数と速度選択に応じて変わること、CORRECT/SKIP の加点、猶予時間と自動スキップ、タイマー0でのリザルト遷移が、Sprint 2 の変更後も回帰していない）
