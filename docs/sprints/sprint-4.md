## Sprint 4: パックの一時共有 ―「その場に居る全員で、3時間だけ同じパックで遊ぶ」

> **改訂**: Sprint 4は一度Evaluatorの合格を得たが、その後ユーザーからのUXフィードバックにより「パック単位でのコード発行・入力」から「**ホストの購入済みパック全てを1回のコードでまとめて共有する**」方式に変更された。以下の記述はこの変更を反映済み。

### ゴール

パックを購入したホストが、その場に居合わせたゲストの端末で**購入済みパックすべてをまとめて一時的に使えるようにする**。サーバーもネット接続も使わず、ホスト端末が生成した**8文字程度の英数字コード**をゲストが手入力するだけで、コードに含まれる全パックが一括で解放され、**発行から3時間で自動的に再ロックされる**ところまでを完成させる。パックごとに個別にコードを発行・入力させることはしない（UX上の要望による）。

「1人が買えば全員が永続的に使えてしまう」状態は作らない。ゲスト端末の解放はあくまで一時的なもので、購入状態とは明確に分離されていることを、このスプリントの成否の中心に置く。

---

### スコープ判断の理由

#### なぜ Sprint 3 から分離したのか

依頼時点では通常課金と一時共有が同じ Sprint 3 に置かれていたが、**2本に分割した**（判断理由の詳細は `sprint-3.md` の「スコープ判断の理由」を参照）。要約すると、

- 一時共有は「購入済みパックのみ共有可能」という前提の上に成り立ち、Sprint 3 のパックモデル・所有判定・ロックUIが確定していないと定義できない（依存が一方向）
- 課金側のリスクは外部依存（ストア設定・実機）、共有側のリスクは自前ロジック（署名・期限判定）で、混ぜると不合格の切り分けが難しくなる
- 合計の契約項目が40を超え、部分的な完成を「完了」と誤認しやすい

これに伴い、リリース準備は Sprint 5 に繰り下げている。

#### Sprint 4 に含めるもの

| 含めるもの | 理由 |
|---|---|
| 共有コードの発行（ホスト側） | 機能の入口。購入済みパックのみを対象にするというガードもここに置かれる |
| 共有コードの入力と一時解放（ゲスト側） | 機能の出口。ここが通って初めて「共有できた」と言える |
| 有効期限と自動再ロック | **一時性を担保する唯一の仕組み**。発行回数・人数の制限を設けない設計にした以上、期限が正しく効かなければ機能全体が「実質的な永続共有」に化ける。本スプリントで最も重要 |
| 不正コードの拒否と、購入状態との分離 | 上と同じ理由。偽造コードが通る、あるいは一時解放が購入済みとして永続化されると、課金の前提が崩れる |

#### Sprint 4 から外すもの

| 外すもの | 理由 |
|---|---|
| QRコード / NFC / 近接通信による受け渡し | spec.md で明示的に対象外。手入力のみとする |
| 発行回数・同時解放人数の制限、発行済みコードの失効（取り消し）操作 | spec.md で「時間経過による自動失効のみで一時性を担保するシンプルな設計」と決定済み。カウント管理はサーバーなしでは正しく実装できない |
| 無料スターターパックの共有 | そもそもロックされていないため共有の意味がない |
| 実機・ストアコンソールでの実購入テスト | Sprint 5 のリリース準備で実施 |
| アイコン・スプラッシュ・ストア掲載情報 | Sprint 5 |

#### 8文字コードについて（承認済みのトレードオフ）

コード長は **8文字程度**とする（ユーザー指定。手入力のしやすさを優先）。10〜14文字と比べて偽造耐性（総当たりで正規コードを捏造されることへの耐性）は下がるが、3時間で自動失効する一時性と、パーティーゲームというリスクの低さを踏まえた**承認済みの判断**。したがって Generator は「桁数を増やして安全側に倒す」判断をしてはならない。

### Generator への実装指針

**署名アルゴリズム・鍵の持ち方・エンコード方式の選択は Generator の裁量に委ねる。** ただし以下は満たすこと。

1. **完全オフライン**。生成も検証もネット接続を必要としない。検証用の鍵はアプリに埋め込む
2. **コードは8文字程度の英数字**。手入力が前提なので、紛らわしい文字（`O`/`0`、`I`/`1`/`l` など）を除いた文字集合を使い、入力時は大文字小文字・空白・ハイフンの揺れを吸収して正規化すること
3. **ペイロードには「発行時点でホストが購入済みの全パックの集合」と絶対時刻の有効期限を含める**（単一パックのIDではなく、複数パックを表せる形にすること。例: パックごとに1ビットを割り当てたビットマスク）。8文字という予算の中でパック集合・期限・署名の3つを収める必要があるため、桁の配分（パック集合に何ビット割くか＝将来のパック追加にどこまで耐えるか、期限の粒度をどこまで粗くするか、署名を何ビットに切り詰めるか）は設計判断として明示的に行い、コード内にコメントで残すこと。**有効期限は絶対時刻として復元できなければならない**（「入力した時点から3時間」ではなく「発行時点から3時間」であること）
4. **時刻を差し替えられる設計にする**。期限判定は `Date.now()` を内部で直接読むのではなく、**現在時刻を引数で受け取る純粋関数**として `packages/game-core` に置く。これにより単体テストで期限前後を検証できる。加えて、**Evaluator が実操作で期限切れを再現できる手段**（開発時のみ有効な時刻オフセット、デバッグ用ストレージキー等。手段は問わない）をアプリ側に用意すること。Evaluator が実際に3時間待つことはできないため、これがないと本スプリントは検証不能になり不合格とする
5. **一時解放の保存先を購入状態と分離する**。Sprint 3 の所有パック（RevenueCat 由来）とは別のストレージ／別の状態として持ち、「所有している」ではなく「一時解放中（期限つき）」として扱う。プレイ可否の判定は両者の和で行ってよいが、**ストア画面の表示・購入の復元・共有コードの発行可否は購入状態のみを見る**こと
6. **エラーは短いコード付きで表示する**（教訓9）。無効なコード・期限切れ・形式不正はそれぞれ区別でき、`APP-` で始まる連番のエラーコードをメッセージに含める

検証環境は Sprint 3 と同じく Expo Web（Playwright）。本機能は純粋な JS ロジックのみで構成されるため、**ネイティブ機能に依存せず Web で全条件を検証できる状態**にすること。

### 実装する機能

- **機能A0: 共有ハブ画面（ホスト/ゲスト選択）**
  ホーム画面に**単一の「パックを共有する」導線**（常に表示、購入状況に関わらない）を置き、タップすると**ホスト/ゲストを選ぶハブ画面**（`/share`）に遷移する。ハブ画面には「ホストとして共有する（コードを発行する）」「ゲストとして受け取る（コードを入力する）」の2択を置く。ホスト側の選択肢は、ホストが何も購入していない場合は非表示または無効化する。ゲスト側の選択肢は所有状況に関わらず常に表示する（ユーザーからのUXフィードバックにより、当初の「ホーム直下に発行画面／入力画面を別々に置く」設計から、ハブ画面を挟む構成へ変更）。

- **機能A: 共有コードの発行（ホスト側）**
  ハブ画面の「ホストとして共有する」から到達する専用画面（`/share-host`）に、**パック単位ではない単一の「共有コードを発行」操作**を置く。押すと、その時点でホストが購入済みの全パックをまとめて表す8文字程度の英数字コードと、その有効期限（発行から3時間後）が残り時間つきで表示される。何を購入済みかに関わらず操作は1つだけで、パックを選ぶUIは設けない。何度でも発行でき、発行回数の制限は設けない。

- **機能B: コード入力と一時解放（ゲスト側）**
  ハブ画面の「ゲストとして受け取る」から到達する「コードを入力」画面（`/enter-code`）。入力されたコードを正規化して署名を検証し、有効ならコードに含まれる**全パック**をその端末上で一時的にプレイ可能にする。成功時は、解放された全パックの名前と、いつまで使えるかを表示する。

- **機能C: 有効期限と自動再ロック**
  一時解放されたパック群は有効期限まで選択・プレイでき、期限を過ぎると全て自動的に再ロックされる。ストア画面とスタート設定画面では、一時解放中の各パックを「購入済み」とは区別できる表示（「一時解放中 / 残りN分」等）にする。期限切れのコードを再入力しても解放されない。

- **機能D: 不正コードの拒否と購入状態からの分離**
  でたらめな文字列、改ざんされたコード、形式不正・空入力をすべてエラーとして扱い、いかなるパックも解放しない。一時解放の状態が購入状態と混ざらないこと（購入の復元で復活しない、ホストが発行しても自分の所有状態が変わらない、ストレージのクリアで消える）を保証する。

### スプリント契約（完了条件）

以下の全条件を満たした場合のみ、このスプリントは完了とする。

**共有ハブ画面（機能A0）**

- [ ] ホーム画面に**単一の「パックを共有する」導線**が存在し（購入状況に関わらず常に表示）、タップするとホスト/ゲストを選ぶハブ画面に遷移する
- [ ] ハブ画面に「ホストとして共有する」「ゲストとして受け取る」の2つの選択肢がある
- [ ] ホストが何も購入していない状態では、ハブ画面の「ホストとして共有する」選択肢が表示されないか操作できない。「ゲストとして受け取る」は購入状況に関わらず常に選択できる
- [ ] 「ホストとして共有する」を選ぶと共有コード発行画面に、「ゲストとして受け取る」を選ぶとコード入力画面に、それぞれ正しく遷移する

**共有コードの発行（機能A）**

- [ ] 共有コード発行画面にパックを選ぶ操作ではなく単一の「共有コードを発行」操作があり、実行すると**8文字程度の英数字コード**が画面に表示される（極端に長い / 短いコードになっていない）
- [ ] 発行されたコードとあわせて、そのコードの有効期限（発行から3時間後）が、残り時間または日時として画面に表示される
- [ ] 発行されるコードには、**発行時点でホストが購入済みの全パックが含まれる**（1パックのみ所有時は1パック、複数パック所有時は全パックが1つのコードに含まれることを、所有パック数を変えて確認できる）
- [ ] 続けて2回発行しても、2回とも発行が成功する（発行回数の上限が設けられていない）

**コード入力と一時解放（機能B）**

- [ ] 「コードを入力」画面が存在し、共有ハブ画面の「ゲストとして受け取る」から到達できる
- [ ] ホスト側で発行した有効なコードを入力すると成功の表示が出て、**コードに含まれる全パックの名前**と利用可能な期限が表示される
- [ ] ホストが複数パックを所有した状態で発行したコードをゲストが入力すると、**その全パックが一括で一時解放される**（1回のコード入力で済み、パックごとに個別入力を求められない）
- [ ] 一時解放後、スタート設定画面でそのパック（複数解放されていればそのいずれか）を選択してゲームを開始でき、出題されるお題がすべてそのパックのカードになる
- [ ] コードの入力は大文字小文字の違い・前後の空白・区切りのハイフンを吸収する（いずれかの揺れを含めて入力しても正しく解放される）
- [ ] ストレージをクリアした別の端末相当の状態（別ブラウザプロファイル等）で同じコードを入力しても、同じように（含まれる全パックが）一時解放される（同時に複数のゲストが使える）

**有効期限と自動再ロック（機能C）**

- [ ] コードの有効性判定が「現在時刻」を引数で受け取る純粋関数として `packages/game-core` に実装されており、単体テストで「期限内は有効 / 期限後は無効」の両方を検証できる
- [ ] ストア画面とスタート設定画面で、一時解放中のパックが「購入済み」とは区別できる表示（残り時間つきの一時解放表示など）になっている
- [ ] Evaluator が時刻を期限後に進める手段（時刻オフセット等）が用意されており、それを使うと**一時解放されていた（複数の場合は全ての）パックがスタート設定画面で再びロック状態になり、選択できなくなる**
- [ ] 期限切れ後に同じコードをもう一度入力しても解放されず、期限切れである旨のエラーが表示される
- [ ] 一時解放中のパックでゲームをプレイしている最中に期限が切れても、アプリがクラッシュせずリザルト画面まで到達できる

**不正コードの拒否（機能D）**

- [ ] でたらめな8文字の文字列を入力するとエラーメッセージが表示され、いかなるパックも解放されない
- [ ] 有効なコードのうち1文字を別の文字に書き換えたコードを入力するとエラーになり、パックが解放されない
- [ ] 空文字・桁数が足りない文字列・使用していない文字を含む文字列を入力しても、クラッシュせずエラーメッセージが表示される
- [ ] 「無効なコード」と「期限切れのコード」で異なるメッセージが表示され、いずれのメッセージにも `APP-` で始まる短いエラーコードが含まれる

**購入状態との分離（機能D）**

- [ ] 一時解放の状態は購入状態とは別に保存され、一時解放したパックがストア画面で「購入済み」と表示されない
- [ ] 一時解放中の端末で「購入を復元する」を実行しても、そのパックが購入済みとして扱われるようにならない
- [ ] ホスト側で共有コードを発行しても、ホスト端末の所有パック一覧・ストア画面の表示が一切変化しない
- [ ] アプリのストレージをクリア（再インストール相当）すると一時解放の状態が消え、対象パックが再びロックされる

**堅牢性・回帰**

- [ ] 幅375pxのビューポートで、コード表示画面とコード入力画面のすべての内容にスクロールで到達でき、横スクロールが発生しない。表示されたコードは8文字が途中で折り返したり省略されたりせず読み取れる
- [ ] Expo Web で発行・入力・期限切れ・不正コードの各操作を一巡しても、未処理例外がコンソールに出ない
- [ ] Sprint 1〜3 の契約が引き続きすべて満たされている（コアゲームループ、遊び方画面、リザルト演出、レビュー訴求のカウント、ストア画面の購入・復元の「準備中」挙動、パック選択と出題の分離が回帰していない）
